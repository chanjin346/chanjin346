** 트러블 슈팅 
1. Refresh Token Race Condition (다중 탭 동시 요청)

  문제 상황
  사용자가 브라우저 탭을 여러 개 열어 동시에 서비스를 이용할 때, Access Token이 만료되면 두 탭이 동시에 /api/auth/refresh를 호출하는 상황이 발생했습니다. 두 트랜잭션이 동일한 Refresh Token 행을 동시에 읽고
   각각 revoke() → 커밋을 시도하면서 MariaDB Error 1020 (Row was updated or deleted by another transaction) 이 터졌습니다.

  원인
  Refresh Token 조회 쿼리에 동시성 제어 수단이 없어서, 두 트랜잭션이 동일 행을 동시에 읽은 뒤 각자 revoked=true로 업데이트하려는 충돌이 발생했습니다.

  해결 
  - RefreshTokenRepository의 조회 메서드에 @Lock(PESSIMISTIC_WRITE) 적용 → 첫 번째 트랜잭션이 행을 잠금
  - 락 타임아웃 3초 설정 → 두 번째 트랜잭션은 대기 후 조건 불일치로 INVALID_REFRESH_TOKEN 예외 발생

  결과
  - 첫 번째 요청만 토큰 갱신 성공
  - 나머지 요청은 안전하게 로그인 화면으로 유도
  - 중복 갱신으로 인한 DB 오류 완전 제거

  ---
  2. Access Token 자동 갱신 버그 2건 (프론트엔드 인터셉터)

  문제 상황 1 — 대기 큐 요청의 _retry 미설정
  여러 요청이 동시에 401을 받으면, 첫 번째 요청만 토큰을 갱신하고 나머지는 큐에서 대기합니다. 갱신 완료 후 대기 요청들을 재시도할 때 _retry 플래그가 없었습니다. 재시도가 실패할 경우 이미 폐기된 Refresh
  Token으로 또다시 갱신을 시도하고, 그 결과 갱신 요청도 실패 → 강제 로그아웃 되는 현상이 발생했습니다.

  문제 상황 2 — newAccessToken에 "undefined" 문자열 저장
  Refresh Token 응답 파싱이 실패하면 newAccessToken 변수가 undefined 상태 그대로 로컬 스토리지에 저장되었습니다. 이후 모든 API 요청 헤더가 Authorization: Bearer undefined로 전송되어 전체 기능이 마비되는
  상황이 발생했습니다.

  해결
  - 버그 1: 큐에서 꺼내 재시도하는 시점에 originalRequest._retry = true 명시 설정
  - 버그 2: !newAccessToken 검증 추가 → 실패 시 throw → clearAuthAndRedirect()로 로그인 화면 이동

  결과
  - 다중 탭 환경에서 토큰 갱신 실패 시 무한 루프 없이 정상 처리
  - undefined 토큰이 저장되는 문제 완전 차단

  3. 인증 보안 취약점 5건 (코드 리뷰 중 자체 발견)

  문제 상황
  초기 구현 이후 코드 리뷰 과정에서 스스로 보안 취약점 5가지를 발견했습니다.

  취약점
  JWT 시크릿 키가 application-dev.yml에 하드코딩 후 git에 그대로 커밋 
  Refresh Token을 DB에 평문 저장  
  Refresh Token 재사용 가능 (Rotation 미적용) 
  탈퇴/비활성 회원의 Access Token이 유효 기간 동안 계속 사용 가능 
  CORS 설정이 WebMvcConfig와 SecurityConfig 두 곳에 이중으로 존재 
 
  해결 
  - application-dev.yml → .gitignore 추가, 환경변수 필수화
  - Refresh Token → SHA-256 해시값으로 변환 후 DB 저장
  - Refresh Token Rotation 도입: 갱신마다 토큰 재발급 + 기존 토큰 즉시 revoke
  - JWT 필터에 isActive 실시간 검증 추가: 탈퇴/비활성 회원 요청 즉시 차단
  - WebMvcConfig 삭제, SecurityConfig 단일 지점으로 CORS 설정 통합

  결과
  - 시크릿 키 외부 유출 가능성 제거
  - DB가 탈취되어도 해시값만 노출, 실제 토큰 복원 불가
  - 토큰 탈취 후 재사용 시도 시 즉시 무효화

  4. 카테고리 필터 적용 시 결과 0건 표시

  문제 상황
  오답노트와 즐겨찾기 페이지에서 카테고리 탭을 클릭하면 해당 카테고리 항목이 분명히 존재함에도 항상 0건이 표시되었습니다.

  원인
  MyBatis XML 쿼리의 카테고리 조건이 완전 일치(=)로 작성되어 있었습니다. 그런데 프론트엔드는 '공항', '교통' 같은 축약된 카테고리명을 전송하고, DB에는 '공항 · 입국', '교통 · 이동' 처럼 더 긴 형태로 저장되어
   있어 매칭이 실패했습니다.

  -- 문제 코드
  AND qs.name = #{category}

  해결 
  WrongAnswerMapper.xml, FavoriteMapper.xml 4개 쿼리 모두 LIKE 조건으로 변경
  -- 수정 코드
  AND qs.name LIKE CONCAT('%', #{category}, '%')

  결과
  - 카테고리 필터 정상 동작
  - 오답노트·즐겨찾기 모두 일괄 수정으로 동일 문제 재발 방지

  5. 프로필 드롭다운이 닫히지 않는 3가지 케이스

  문제 상황
  로그인 후 프로필 드롭다운을 열면 다음 3가지 상황에서 드롭다운이 닫히지 않았습니다.
  1. 네비게이션 링크를 클릭해 다른 페이지로 이동해도 드롭다운이 그대로 남음
  2. 드롭다운 내부의 "마이페이지", "로그아웃" 버튼을 클릭해도 닫히지 않음
  3. 화면의 빈 영역을 클릭해도 닫히지 않음

  원인
  - 케이스 1: 라우트 변경 이벤트를 감지하는 코드 없음
  - 케이스 2: 버튼 클릭 이벤트가 버블링되어 드롭다운 토글 로직과 충돌
  - 케이스 3: 외부 클릭을 감지하는 오버레이 레이어가 화면 전체를 덮지 않음

  해결 
  - 케이스 1: watch(() => route.path, () => closeDropdown()) 추가
  - 케이스 2: 버튼에 @click.stop 수식어로 이벤트 버블링 차단
  - 케이스 3: profile-overlay에 position: fixed; inset: 0 적용 → 화면 전체를 덮는 투명 레이어

  결과
  세 케이스 모두 정상 동작, 드롭다운이 의도한 상황에서만 열리고 닫힘

  6. 브라우저 기본 alert/confirm 의 UX 불일치

  문제 상황
  도장 삭제, 미션 제거, 에러 안내 등의 상황에서 브라우저 내장 alert() / confirm() 을 그대로 사용하고 있었습니다. 내장 다이얼로그는 OS 스타일 그대로 노출되어 프로젝트의 여권/여행 테마 디자인과 완전히
  동떨어진 외관이 표시되었고, 스타일 커스터마이징이 불가능했습니다.

  해결
  - useModal.js composable 신규 작성 — 싱글톤 패턴 + Promise 기반으로 await showConfirm() 형태의 간결한 사용 제공
  - AppModal.vue 신규 작성 — <Teleport>로 <body> 직하 렌더링 (z-index 충돌 방지), 페이드+스케일 애니메이션 적용
  - App.vue에 전역 등록 → 이후 모든 뷰에서 import 한 줄로 사용 가능
  - FavoriteListView.vue, WrongAnswerListView.vue 내 alert/confirm 전수 교체

  결과
  - 디자인 시스템에 맞는 일관된 모달 UI 제공
  - 기존 코드 변경 최소화(호출 방식이 동일한 async/await 형태)

  7. 배지 달성 조건과 진행도를 알 수 없음

  문제 상황 1 — 진행도 표시 없음
  여행기록 페이지의 배지 섹션은 달성 여부(잠금/해제)만 보여줬습니다. 사용자가 배지를 얻으려면 얼마나 더 해야 하는지, 현재 어느 정도 진행됐는지 전혀 알 수 없었습니다.

  해결
  - 각 배지의 current / max / pct 를 computed 배열로 통합 관리
  - 숫자 텍스트 + 프로그레스 바 조합으로 진행도 시각화
  - pct = Math.min(current / max * 100, 100)으로 목표 초과 시 100% 고정

  문제 상황 2 — 달성 조건 문구 없음
  배지 아이콘만 표시되고 어떤 조건을 달성해야 배지를 얻는지 설명이 없어, 사용자가 배지의 의미를 직관적으로 알기 어려웠습니다.

  해결 
  - 각 배지 데이터에 desc 필드(달성 조건 문구) 추가
  - 순수 CSS [data-tip]::after 가상 요소로 hover 툴팁 구현 (JavaScript 불필요)
  - fade-in 0.18초 애니메이션, 아이콘 위 중앙 정렬

  결과
  - 사용자가 현재 진행 상황과 목표를 수치로 즉시 파악 가능
  - 배지 위에 마우스를 올리면 달성 조건이 한 줄로 표시
